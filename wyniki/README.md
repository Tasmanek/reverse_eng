## Otwieranie i edycja

1. Otwórz https://demo.bpmn.io/ i przeciągnij wybrany plik `.bpmn` na edytor albo użyj polecenia otwarcia pliku.
2. Widok główny zawiera pule, tory, przepływ importu i niezależne procesy tła. Dopasuj powiększenie, a następnie przybliż interesującą pulę.
3. Podprocesy mają znak „+”. W bpmn-js skorzystaj z nawigacji do wnętrza podprocesu (drill-down, zwykle przycisk rozwinięcia lub menu kontekstowe); powrót prowadzi przez nawigację nadrzędnego diagramu. Każde wnętrze ma własny BPMNPlane i pełne DI. Nie są to odnośniki wymagające drugiego pliku.
4. Po zapisaniu przez edytor zachowaj format BPMN XML. L1 i L2 nie mają zewnętrznych callActivity; każdy plik jest samodzielny.
5. `bpmn:documentation` zawiera reguły, ograniczenia i źródła. Sam demo.bpmn.io może nie udostępniać edytora dokumentacji; treść pozostaje w XML. Ważne decyzje i skutki są również widoczne w nazwach i przepływach.

Modele są niewykonywalne (`isExecutable=false`). Wyrażenia warunków, harmonogramu i liczności wieloinstancyjnej są opisowe; nie służą uruchamianiu w silniku. Zgodność z Visual Paradigm nie była testowana. Narzędzie bez obsługi osobnych płaszczyzn podprocesów może wymagać ich rozwinięcia w swoim interfejsie; nie deklarujemy bezstratnego importu do tego produktu.

## Semantyka i sposób czytania

- Pule „Portal” rozdzielają autonomiczne procesy wykonywania pracy, nie organizacje ani fizyczne serwery. Administrator i harmonogram są torami odpowiedzialności. Serwer instytucji jest pulą bez rozwiniętego procesu.
- Przepływy sekwencji nie przekraczają puli ani granicy podprocesu. Przepływy komunikatów występują wyłącznie pomiędzy pulami. Komunikaty zaczepione do obwiedni puli zbiorczo reprezentują zlecenia wykonywane przez zadania wewnątrz rozwijanych podprocesów.
- Zlecenia Celery i odpowiedzi HTTP nie są utożsamiane: zlecenie uruchamia niezależną instancję, a synchroniczne żądania HTTP są pokazane zbiorczo na współpracy i szczegółowo w zadaniach. Komunikaty HTTP nie są dodatkowymi wywołaniami po końcu importu. Brak odpowiedzi i błąd połączenia są lokalnymi wynikami zadania, a nie komunikatem wysłanym przez serwer instytucji.
- Odebranie zlecenia ma zdarzenie początkowe komunikatu. Nie ma bramki łączącej wszystkie prace tła przed zakończeniem importu. Nie określono kolejności wykonania między kolejkami.
- Wieloinstancja sekwencyjna oznacza pętlę po wskazanej liście. DGA CKAN iteruje wyłącznie po oznaczonych zasobach; zero takich zasobów pomija te kontrole. Walidacja list nie oznacza osobnego importu każdego zbioru.
- Zdarzenia błędu są analitycznym odwzorowaniem propagacji wyniku lub wyjątku do otaczającego etapu. Szczególnie U-15: granica błędu nie oznacza dopisania w kodzie handlera, rollbacku ani automatycznej naprawy.
- Nazwane zakończenia rozróżniają pominięcie, ERROR, OK, OK_PARTIAL, przerwany zapis i problemy z zadaniem zasobu. Nie stosujemy końca terminującego do zatrzymywania niezależnych procesów.
